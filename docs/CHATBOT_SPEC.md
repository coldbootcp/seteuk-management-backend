## 2. 이번에 고친 것

참고용입니다. 아래 갭 목록에는 포함되지 않습니다.

1. **스트림이 실패해도 도구 실행 기록이 남는다.** 이전에는 LLM이 도중에 죽으면
   `applied_actions`를 저장하지 않고 빠져나갔습니다. 도구는 이미 커밋을 끝낸
   뒤라, **기록은 바뀌었는데 무엇이 바뀌었는지 아무 데도 남지 않는** 상태가
   됐습니다. 이제 실패·취소 모두 저장한 뒤 이벤트를 냅니다(취소는 `asyncio.shield`로
   저장까지 끊기지 않게 보호).
2. **대화 목록 정렬이 실제로 최근순이 됐다.** 메시지를 추가해도 `conversations`
   행은 UPDATE되지 않아 `onupdate`가 걸리지 않았고, 첫 메시지에서 제목이 채워진
   뒤로는 `updated_at`이 얼어붙었습니다. 방금 대화한 방이 목록 아래에 남았습니다.
3. 대화가 스트림 직전에 삭제되면 예외가 새어 나가던 것을 SSE `error`로 바꿨습니다.
4. 컨텍스트의 수상·봉사에 `ORDER BY`가 없어, 상한(30/20건)에 걸리면 **DB가 임의로
   고른** 행이 실렸습니다. 같은 질문에 매번 다른 근거를 들 수 있었습니다. 최신순으로
   고정했습니다.
5. `add_award` / `add_volunteer_record`가 `raw_date`만 받아 정규화된 `date`를
   영영 채우지 못했습니다("날짜는 항상 ISO 8601로 정규화" 원칙 위반). ISO `date`
   인자를 추가했습니다.

## 3. 갭 목록

우선순위는 제 판단입니다. 동의하지 않으시면 조정해 주세요.

### 🔴 즉시 수정 권장

#### S-1. 수정 도구가 LLM이 보낸 필드를 화이트리스트 없이 그대로 씁니다

`update_activity`와 `update_plan`은 인자에서 id만 빼고 나머지를 그대로
`setattr` 합니다(`record_service.update_record`, `plan_service.update_plan_item`).
도구 스펙에 없는 키를 모델이 지어내도 걸러지지 않습니다.

실질적 위험은 두 가지입니다.

- `source_upload_id`를 쓸 수 있습니다. API_SPEC은 "생성 요청으로는 이 값을 지정할
  수 없게 해 재업로드 삭제 규칙을 우회할 수 없도록 함"이라고 못박아 두었는데,
  **챗봇 경로가 이 보호를 통과합니다.**
- `user_id`를 쓸 수 있습니다. 모델이 실제로 이럴 가능성은 낮지만, 남의 데이터로
  행을 옮기는 무방비 쓰기 경로가 열려 있는 것 자체가 문제입니다.

수정은 작습니다 — 도구별 허용 필드 집합을 두고 그 외는 버리면 됩니다.

> **결정:** _(이대로 고칠까요? / 다르게 가고 싶다면 어떻게?)_

### 🟠 기능이 실제로 모자란 곳

#### A-1. 컨텍스트에 없는 기록은 챗봇이 찾아볼 방법이 아예 없습니다

컨텍스트 상한은 활동 80건입니다. 실제 검증 계정은 활동이 **120건**이었습니다.
잘린 40건에 대해 챗봇이 할 수 있는 일은 "기록이 더 있다"고 아는 것뿐입니다
(`counts`). **조회 도구가 하나도 없어서** 특정 활동을 찾아보거나 상세를 읽을
수단이 없습니다.

"1학년 때 그 로봇 활동 기억나?"에 답하지 못하는 지점입니다.

선택지:
- (a) 조회 도구 추가 — `search_records(query, kind)`, `get_activity(id)` 등
- (b) 상한을 올리고 설명을 더 줄여서 더 많이 싣기 (토큰 비용 증가)
- (c) 임베딩 검색 (인프라 추가, 현재 스택에 없음)

추천은 **(a)** 입니다. 수정 모드가 아니라 두 모드 모두에서 쓸 수 있는 읽기 도구로
두면 일반 모드의 답변 품질도 같이 올라갑니다.

> **결정:** _______

#### A-2. 진단 결과를 절반만 봅니다

컨텍스트에 들어가는 진단은 SWOT + `career_thread`뿐입니다.
`semester_reviews`, `activity_inventory`, `knowledge_graph_links`는 빠져 있습니다.
"내 활동 중에 뭐가 서로 이어져 있어?"처럼 지식 그래프를 물으면 답하지 못합니다.

> **결정:** _(어느 섹션까지 넣을까요? 전부 넣으면 컨텍스트가 꽤 커집니다)_

#### A-3. 대화 제목이 첫 메시지 원문을 60자로 자른 것입니다

`"어제 확률적으로 생각하기 다 읽었어요. 2학년 2학기 수학Ⅱ와 연결해서 기록해주…"`
같은 제목이 목록에 남습니다.

선택지:
- (a) 그대로 둔다(LLM 호출 0회)
- (b) 첫 턴이 끝난 뒤 짧은 LLM 호출로 제목 생성(대화당 1회, 저렴한 편)
- (c) 사용자가 직접 제목을 고치는 `PATCH /conversations/{id}`

### 🟡 신뢰성 · 운영

#### R-1. 한 턴 안에서 도구가 부분만 적용될 수 있습니다

도구는 각각 즉시 커밋합니다. 한 턴에 3개를 부르고 두 번째가 실패하면 첫 번째는
남고 세 번째는 실행되지 않습니다. 사용자에게는 "일부만 기록된" 상태로 보입니다.

한 턴을 트랜잭션으로 묶는 방법이 있지만, 도구가 호출하는 서비스 함수들이 각자
커밋하도록 짜여 있어 구조를 꽤 건드려야 합니다. **지금은 부분 적용을 허용하되
`applied_actions`로 무엇이 됐는지 정확히 보여주는** 쪽으로 가 있습니다.

> **결정:** _(이대로 둘까요, 트랜잭션으로 묶을까요?)_

#### R-2. 사용량 한도가 요청 단위입니다

한 턴에 도구 루프가 4라운드 돌면 LLM 호출은 4회지만 `usage_events`에는 1건만
남습니다. 실제 비용과 한도가 어긋납니다. 토큰 사용량 기록도 없습니다.

> **결정:** _(호출 단위로 셀까요? 토큰까지 기록할까요?)_

#### R-3. `max_tokens` / `temperature`를 지정하지 않습니다

`app/services/llm.py`가 모델 기본값에 맡깁니다. 답변이 지나치게 길어지는 것을
막는 상한이 없습니다.

> **결정:** _______

#### R-4. 온보딩 전에는 도구가 DB 에러 문자열을 그대로 노출합니다

`add_reading` 등은 `grade`가 없으면 `user.current_grade`로 대체하는데, 온보딩
전에는 이 값이 `NULL`이라 NOT NULL 위반이 납니다. 그 예외 문자열
(`IntegrityError: ...`)이 그대로 챗봇에게 전달되고, 챗봇이 그걸 학생에게
설명합니다. 실제 서비스 흐름에서는 온보딩이 강제라 도달하기 어렵지만, 도구가
스스로를 지키지는 못하는 상태입니다.

> **결정:** _______

### 🟢 품질 · 안전

#### Q-1. 프롬프트 인젝션에 대한 방어가 없습니다

생기부에서 파싱한 활동 `description`이 시스템 프롬프트의 `<학생_데이터>` 안에
그대로 들어갑니다. 학생이 자기 기록에 "이전 지시를 무시하라" 같은 문장을 넣으면
프롬프트에 섞입니다. 자기 데이터로 자기 챗봇을 흔드는 것이라 피해 범위는 자신에게
한정되지만, 도구가 실제 쓰기 권한을 갖고 있다는 점은 짚어 둘 만합니다.

> **결정:** _(구분자 강화 정도로 충분할까요, 아니면 지금은 무시할까요?)_

#### Q-2. 말투·형식 규칙이 프롬프트뿐이고 검증이 없습니다

존댓말 규칙은 실제 검증에서 한 번 어긋난 적이 있어 프롬프트를 강화한 이력이
있습니다(CLAUDE.md). 지금은 출력 검사가 없어 다시 어긋나도 알 수 없습니다.

> **결정:** _______

#### Q-3. 삭제 요청에 대한 안내 문구가 없습니다

삭제 도구는 의도적으로 없습니다. 그런데 "잘못 기록했어요, 지워주세요"라고 했을 때
무엇을 안내할지가 프롬프트에 없어, 모델이 그때그때 다르게 답합니다.
"탭에서 직접 삭제해 주세요"라고 일관되게 안내하도록 한 줄 넣으면 됩니다.

## 4. 우선순위 제안

제가 짠다면 이 순서입니다.

1. **S-1** (화이트리스트) — 작고, 보호 규칙을 되돌리는 일입니다
2. **A-1** (조회 도구) — 챗봇이 "모른다"고 답하는 가장 흔한 원인
3. **Q-3** (삭제 안내) — 프롬프트 한 줄
4. **A-3** (제목) · **A-5** (페이지네이션) — 사용자 눈에 바로 보이는 것
5. **A-2** (진단 섹션 확장) · **A-6** (히스토리 요약)
6. **R-2** (사용량 계측) · **R-3** (`max_tokens`)
7. 나머지

## 5. 명세하지 않은 것

의도적으로 비워 둔 자리입니다. 필요하다고 판단되면 알려 주세요.

- 대화 공유 / 내보내기
- 음성 입력
- 첨부파일(이미지·PDF)을 대화에 올리기
- 여러 학생(선생님 계정)을 한 챗봇에서 다루기
- 대화 검색
