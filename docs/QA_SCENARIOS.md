# 출시 전 학생 이용 시나리오 점검표

작성: 2026-10-05 (출시 전날). 학생이 세특연구소를 처음 만나 생기부를 올리고 매일 쓰기까지
일어날 수 있는 상황을 모두 적고, 각 상황에서 **오류 없이 동작하는지**와 **학생이 무엇을 해야
하는지 이해할 수 있는지**를 함께 본다.

- 운영: `manage.seteuk.site` (백엔드 `seteuk-backend`, AI는 Gemini `gemini-3.8-flash`)
- 회원가입은 닫혀 있다. 학생은 운영자가 만들어 준 체험 계정(`…@seteuk.site`, 이메일 인증
  건너뜀)으로 들어온다.
- 점검 결과 표기: ✅ 통과 · ⚠️ 동작은 하지만 이해하기 어렵거나 개선 필요 · ❌ 오류 · ➖ 이번에
  점검하지 못함(이유 적음)

## 점검 방법

| 환경 | 무엇을 | 왜 |
|---|---|---|
| 로컬(운영과 같은 코드 + 실제 Gemini 키, 검증 전용 DB `seteuk_e2e`) | 여러 계정 상태가 필요한 시나리오, 실패·예외 파일, 탈퇴처럼 되돌리기 어려운 동작 | 운영 계정 하나로는 상태를 되돌릴 수 없고, 운영 DB를 시험 데이터로 채우지 않기 위해 |
| 운영(체험 계정 1개, 소유자가 직접 로그인) | 실제 학생이 밟는 대표 경로 전체 | 배포 설정·키·도메인·보안 정책(CSP)은 운영에서만 확인된다 |

검증용 생기부: `tmp2.pdf`(새 서식, 2025학년도 입학 2학년 2학기 학생 — 정상 경로),
`tmp.pdf`(2022학년도 입학 졸업생 — 거절 경로). 둘 다 실제 기록을 바탕으로 해 저장소에
올리지 않는다.

## 남은 위험·결정할 것

- **휴대폰 학생은 튜토리얼을 못 봄**(769px 미만에서 꺼짐). 휴대폰용 튜토리얼이 필요하면 별도 설계.
- **운영 배포마다 `dev-manage` 도메인이 운영 배포로 옮겨감** — 배포 후 `vercel alias set <개발 프리뷰> dev-manage.seteuk.site`.
- **회원가입은 닫혔지만 `ACCESS_ALLOWLIST`가 비어 있어 서버의 가입·구글 가입 API는 열려 있음.**
- **개발 DB 메모리 256MB** — 개발 서버도 여러 명이 쓰면 같은 증상이 날 수 있음.
- **처리방침 "시행 7일 전 고지"** 약속과 이번 개정(10/6 시행) 시점이 맞지 않음.
- 점검하지 못한 항목(➖): 무차별 대입 한도, 1학년 1학기 생기부, 시간표 편집, 프로필 수정, 상담 중 진로 변경·흐름 다시 조율.
